# 2026-09-23、24、26、27 日评复算材料

`audited_4days_heroes.json` 逐行记录对应截图、六人名单身份、英雄图像识别候选、整数占比、截图上以“万／k”精度显示的输出及真实承伤。英雄图标通过与公开英雄头像比对识别，候选差距较小的结果做了人工抽查；原始截图见 `../screenshots/`，个别图标仍可人工复核。

`kda_verified.json` 按日期、场次、截图中己方五人从上到下的顺序保存人工逐行核对的 `[击杀, 死亡, 助攻]`。原始 OCR 部分将数字粘连到旁边的评分，不能直接使用；此文件所列每场五人的击杀和均与截图上的己方总击杀一致。

`recalculate_four_days.py` 按 HD-RATING-2.1 从上述转录、`../references/aramkit_v16.19_全分段_2026-09-28.json` 和 `../docs/海斗日评与月评评分标准.md` 复算四份日报与 CSV。运行：

```bash
python repro/recalculate_four_days.py
```

脚本在同一场次集合时展示可比较的同场名次及九方案名次范围；参赛场次不同时，所有人按日分从高到低列出分数序位，但这不代表同条件实力名次。9 月 27 日另列 Let325544 所参加 M10、M11 的五人共同对局对比。

脚本运行末尾会调用 `build_summary_cards.py`：从逐场 CSV 和 [Riot Data Dragon 16.19.1 冻结英雄定位](../references/riot_ddragon_16.19.1_英雄定位.json)制作四张日报一图流及 9 月阶段月评一图流，并把按分排序、逐人点评嵌进 Markdown 日报／阶段月报。图片使用 Pillow 与中文字体；未安装字体时通过 `HAIDOU_CJK_FONT` 指向系统 OTF/TTF 字体。也可单独运行：

```bash
python repro/build_summary_cards.py --month 2026-09
```

阶段月评只汇总已收集且完整评分的游戏日。核对完月内全部对局、且游戏月已结束后，可显式加入 `--final` 生成正式月评图；脚本无法自行发现未提交的对局，因此使用者仍需核对完整性。

脚本仅为 OCR 缺失的五个原值做了显式修正，对应原图：23 日 M01 第 5 行真实承伤 4.8 万、M03 第 1 和第 3 行输出分别 4.7 万与 4.8 万、M04 第 3 行真实承伤 4.7 万，24 日 M05 第 1 行真实承伤 4.4 万。单局团队占比始终使用截图上的整数百分比，五名选手全计入分母和同场环境系数的计算；只为六人名单中的参赛者出分。参考站点未证明“自我减免”与桌面端“自我减伤”完全同口径，因此结果仍需标注跨站承伤口径待核实。

`逐场评分明细_v2.csv` 与 `日评汇总_v2.csv` 是保留的 HD-RATING-2.0 结果，四日 `历史日评_HD-RATING-2.0.md` 保留对应文字说明。运行脚本只刷新 `.v2.1.csv`、四日日报、一图流及阶段月报，不会改变 v2.0 原值。
